# 10. 기능 — 회원가입 · 로그인 · 역할 격리

## 핵심

가입은 **브라우저 검사 + 서버 검사** 두 번, 로그인은 **세션에 `loginMember` 저장**, 모든 요청은 **BaseServlet 이 역할을 확인**한다.

## 회원가입 흐름

| 단계 | 내용 |
|---|---|
| 화면 | `member/join.jsp` — 아이디 · 비밀번호 · 확인 · 이름 · 이메일 · 연락처 |
| 중복확인 | 버튼 → `ui.js` 가 `XMLHttpRequest` 로 `GET /member/idcheck?loginId=` 호출 (페이지 이동 없음) → 결과를 `data-checked-value` 에 저장. **확인한 값과 지금 값이 같아야** 제출됨 |
| 브라우저 검사 | `validate.js` — `data-rule` 붙은 칸만 검사, 실패하면 `alert` 후 제출 막음 |
| 호출 URL | `POST /member/join` |
| 클래스 · 메서드 | `MemberServlet.post()` → `join()` → `checkPassword()` · `checkProfile()` → `MemberDAO.exists()` → `MemberDAO.insert()` |
| SQL | `SELECT … FROM member WHERE login_id = ?` (중복) → `INSERT INTO member (…, role) VALUES (…, 'USER')` |
| 성공 | `flash("회원가입이 완료되었습니다…")` → `/member/login?loginId=…` 로 redirect (아이디가 미리 채워짐) |
| 실패 | `throw new Fail("메시지")` → 같은 화면을 입력값 유지한 채 다시 그림 |

비밀번호 규칙: 영문 · 숫자 · 특수문자 각 1자 이상, 8~20자. **같은 정규식이 `validate.js` 와 `MemberServlet.PASSWORD_REGEX` 에 둘 다** 있다 (브라우저는 편의, 서버가 진짜 판정).

## 로그인 흐름

```
POST /member/login
 → MemberDAO.byLoginId(loginId)
 → 없거나 비밀번호 다름 → "아이디 또는 비밀번호가 올바르지 않습니다."
 → status = 'LEFT'     → "탈퇴한 계정입니다."
 → session.invalidate() 후 새 세션에 loginMember 저장   ← 세션 고정 공격 방지
 → returnUrl 이 우리 사이트 주소이고, 그 역할이 갈 수 있는 곳이면 그리로, 아니면 역할별 홈
```

## 역할 격리 (BaseServlet.allowed)

| 경로 | 비로그인 | USER | ADMIN |
|---|---|---|---|
| 메인 · 상품 · 조합 맞추기 · 공지 | ○ | ○ | ○ |
| `/cart` `/order` `/mypage` `/wish` | 로그인 화면으로 (돌아올 주소 기억) | ○ | ✕ 홈으로 + 안내 |
| `/admin/**` | 로그인 화면으로 | ✕ 홈으로 + 안내 | ○ |

- 판정은 `path.startsWith("/admin")` 와 정규식 `/(cart|order|mypage|wish)(/.*)?` 두 줄.
- JSP 에서도 `me.role` 로 버튼을 숨기지만(예: 관리자에게 "장바구니 담기" 안 보임), **진짜 막는 곳은 서버**.

## 예외 처리

- 입력 오류 → `Fail` (RuntimeException) → 화면에 메시지.
- DB 오류 → `SQLException` → `BaseServlet.run()` 이 `ServletException` 으로 감싸 → `web.xml` 의 500 오류 화면.

## 발표 때 조심할 점

- **비밀번호를 평문으로 저장 · 비교한다** (`password.equals(member.getPassword())`). 수업 범위상 단순하게 둔 것이고, 실서비스라면 BCrypt 같은 해시를 써야 한다고 먼저 말하는 게 좋다.
- 로그인 화면에 시연 계정 비밀번호가 표시된다 (시연용).
