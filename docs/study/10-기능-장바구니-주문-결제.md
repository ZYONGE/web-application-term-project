# 10. 기능 — 장바구니 → 주문 → 결제 → 취소 (가장 중요)

## 핵심

결제는 **주문 · 주문상품 · 재고 차감 · 결제 · 배송 · 배송이력 · 장바구니 비우기** 를 **한 트랜잭션**으로 묶는다. 하나라도 실패하면 전부 취소(rollback).

## 1) 장바구니 담기

| 단계 | 내용 |
|---|---|
| 호출 | `POST /cart/add` (productId, quantity=섭취 일수, back) |
| 메서드 | `CartServlet.post()` → `checkDays()` → `ProductDAO.byId()` → `CartDAO.add()` |
| 검사 | 일수 1~상한, 판매중인지, `재고 >= 일수` |
| SQL | `INSERT INTO cart (member_id, product_id, quantity) VALUES (?,?,?) ON DUPLICATE KEY UPDATE quantity = ?` |
| 결과 | "14일분을 장바구니에 담았습니다" 알림 후 보던 화면(back)으로 |

같은 상품을 또 담으면 `UNIQUE(member_id, product_id)` 덕분에 새 행이 아니라 **일수가 새 값으로 바뀐다**.

## 2) 장바구니 화면

- `GET /cart/list` → `CartDAO.cart(memberId, true)` → 상품 합계 · 배송비 · 결제 예정 금액
- 배송비: `ConfigDAO.deliveryFee(합계)` — 합계가 0 이면 0, 무료배송 기준 이상이면 0, 아니면 기본 배송비 (설정 테이블 값)
- 판매 중지 · 재고 부족 상품은 "주문 불가"로 표시하고 합계에서 뺀다
- 담은 상품끼리 **동시 섭취 경고**도 보여 준다 (→ 커스텀 조합 노트)

## 3) 주문서 → 결제

```
GET  /order/form   주문서 (기본 배송지 채움, 카카오 우편번호 검색)
POST /order/pay    OrderServlet.pay()
```

`OrderServlet.pay()` 순서:

```java
검사: 받는 사람 · 연락처 · 주소 · 결제수단(카드/무통장/간편결제)
DB.begin();
try {
    cart = CartDAO.cart(memberId, false);          // 비었으면 Fail
    total = 주문 가능한 것만 합계;  fee = 배송비;
    orderId = OrderDAO.insertOrder(...);           // INSERT orders
    for (각 주문 가능 상품) {
        OrderDAO.insertItem(orderId, item, 트랙이면 구성 스냅샷);   // INSERT order_item
        if (ProductDAO.decreaseStock(id, 일수) == 0)              // UPDATE … WHERE stock >= ?
            throw new Fail("재고가 부족합니다");                    // → 전부 rollback
    }
    OrderDAO.insertPaymentAndDelivery(orderId, method, total + fee);  // payment · delivery · 이력
    CartDAO.clear(memberId);                       // 장바구니 비우기
    DB.commit();
} finally {
    DB.end();   // commit 안 됐으면 rollback + 커넥션 반납
}
```

### 왜 `WHERE stock >= ?` 인가 (동시 주문 대비)

두 사람이 마지막 재고를 동시에 사면, 먼저 UPDATE 한 쪽만 1행이 바뀌고 뒤쪽은 **0행** → Fail → rollback. 재고가 음수가 되지 않는다. "읽고 → 계산하고 → 쓰기" 대신 **DB 가 조건과 차감을 한 번에** 한다.

### 주문 번호

INSERT 때 임시 번호 → 바로 `UPDATE … order_no = CONCAT(날짜, '-', LPAD(order_id, 4, '0'))` → 예 `20261124-1264`.

## 4) 주문 취소

| 항목 | 내용 |
|---|---|
| 호출 | `POST /order/cancel` (회원) · `POST /admin/orders mode=cancel` (관리자) — 둘 다 `OrderServlet.cancel()` |
| 조건 | 본인 주문 · 아직 정상 · 배송 단계가 **결제완료 또는 상품준비** (발송 전) |
| 트랜잭션 | 주문 상태 '취소' → 결제 '환불' → 상품마다 `increaseStock` → (관리자면 admin_log) → commit |
| 중복 방지 | `UPDATE orders … WHERE order_id = ? AND order_status = '정상'` 이 0행이면 "이미 취소된 주문" |

## 예외 처리 정리

| 상황 | 결과 |
|---|---|
| 입력 누락 · 재고 부족 · 이미 취소 | `Fail` → 알림 + 원래 화면 (DB 는 rollback) |
| DB 오류 | `SQLException` → `DB.end()` rollback → 500 오류 화면 |

## 알려진 한계 (Q&A 대비)

- 결제는 **모의 결제** (실제 PG 연동 없음, 과제 규칙상 실결제 금지).
- 결제 후 `CartDAO.clear()` 가 **주문하지 못한 상품까지** 장바구니에서 지운다.
