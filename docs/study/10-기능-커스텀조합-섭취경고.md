# 10. 기능 — 조합 맞추기 · 동시 섭취 경고 (이 쇼핑몰만의 기능)

## 핵심

고른 상품을 **낱개 단위로 펼친 뒤**(트랙은 구성품으로), 그 안에서 ① 금지 조합 쌍 ② 같은 영양제 두 번 이상을 찾아 경고한다. 경고는 **안내만** 하고 구매를 막지 않는다.

## 화면과 URL

| 단계 | 내용 |
|---|---|
| 화면 | `custom/index.jsp` — 왼쪽 카테고리 탭에서 낱개 체크, 오른쪽에 고른 목록 · 일수 · 합계 · 경고 |
| 호출 | `GET /custom?pick=1,2,3&days=30` (주소 자체가 조합 → 공유 가능) · `GET /custom?combo=1` (내 조합 불러오기) |
| 저장 | `POST /mypage/combo/save` (USER 만) → `CartDAO.saveCombo()` |
| 메서드 | `CustomServlet.get()` → `ProductDAO`(판매 중 낱개) · `ConflictDAO.all()` · `ConflictDAO.warnings(pickedIds)` |

## 화면 안에서 (서버 왕복 없음)

`custom.js` 가 체크 · 일수 변경 때마다 `render()`:

1. 1포 가격 합 × 일수 = 상품 합계
2. 배송비 = 합계가 0 이면 0, 무료배송 기준 미만이면 기본 배송비 (**서버 `ConfigDAO.deliveryFee` 와 같은 식**)
3. 금지 조합 목록(서버가 처음에 내려 준 `conflicts`)과 비교해 경고 상자 표시
4. `history.replaceState` 로 주소창을 `?pick=…&days=…` 로 바꿈 → 새로고침 · 링크 공유해도 그대로

## 서버 쪽 경고 계산 — `ConflictDAO.warnings()`

```
고른 id 들
 → 트랙이면 구성 낱개로 펼침 (어느 트랙에서 왔는지 이름도 기억)
 → 펼친 낱개 id 집합에서 supplement_conflict 에 걸린 쌍 찾기   → "동시 섭취 주의"
 → 같은 낱개가 2번 이상 나오면                                → "중복 섭취"
```

예: "종합비타민" + "비타민A" → 시드의 금지 조합 → "비타민A 를 과다 섭취할 수 있습니다".
예: 트랙 A 와 트랙 B 에 둘 다 오메가3 → "'오메가3' 이(가) 2번 들어갑니다".

같은 `warnings()` 를 **장바구니 · 상품 상세 · 조합 맞추기** 세 곳이 같이 쓴다.

## DB

| 테이블 | 역할 |
|---|---|
| `supplement_conflict` | 금지 쌍 (`product_a < product_b`, 경고 문구) — 관리자가 `/admin/conflicts` 에서 관리 |
| `track_item` | 트랙 → 구성 낱개 |
| `combo` · `combo_item` | 내 조합 (이름 · 일수 · 낱개들). 같은 이름 저장 시 덮어쓸지 confirm |

## 왜 이렇게 만들었나 (발표 포인트)

- 영양제 쇼핑몰의 실제 고민(겹쳐 먹기, 같이 먹으면 안 되는 것)을 **데이터(쌍 테이블)** 로 풀었다. 규칙을 코드에 박지 않아서 관리자가 화면에서 추가 · 수정한다.
- 계산은 브라우저에서 즉시, 최종 판정 · 저장은 서버에서 — 빠르면서도 서버가 기준이다.
